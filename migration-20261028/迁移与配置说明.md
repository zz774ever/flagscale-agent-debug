这份迁移包保存了本次修复后的 FlagScale-Agent 源码、完整修复补丁和配置模板。
下面按 Linux / Bash 说明，直接使用你已有的安装方式，无需另建运行环境。
这次 HTTP 400 的直接原因是请求协议不匹配；修复的重点是代码适配和 API 配置。

1. **先了解本次改动**

   最初遇到两个独立问题：配置被启动参数的默认值覆盖，以及模型请求使用了不受支持的协议。

   | 文件 | 改动与目的 |
   | --- | --- |
   | `flagscale_agent/cli.py` | 未显式传入的 provider/model/base_url 不再覆盖 YAML；增加 `--openai-api` 参数。 |
   | `flagscale_agent/react/config.py` | 先合并 YAML 与显式参数，再解析环境变量和默认值；增加 `openai_api` 配置；切换提供商时重新解析对应配置。 |
   | `flagscale_agent/react/providers/openai_provider.py` | 增加真正的 `/responses` 请求、输入消息转换、工具定义转换、普通及流式响应解析、工具结果回传、推理状态保留、错误和截断处理；保留 Chat Completions 分支。 |
   | `flagscale_agent/react/providers/__init__.py` | 将协议配置传给 OpenAI provider。 |
   | `flagscale_agent/react/agent.py` | 接收 Responses 流事件，将推理状态留在历史中供后续请求使用，并记录截断。 |
   | `pyproject.toml` | OpenAI SDK 最低版本从 `1.0.0` 提高到 `1.66.0`，以支持 Responses。 |
   | `tests/test_config_provider_override.py` | 增加配置保留、提供商切换与命令行配置加载的回归测试。 |
   | `tests/test_openai_responses.py` | 新增协议切换、实际 SDK 请求格式、流式响应、并行工具参数、两轮工具交互、推理状态、错误和截断测试。 |
   | `README.md`、`README_zh.md`、`examples/agent_config.yaml` | 补充配置和启动说明。 |

   原补丁把工具定义从 `{"type":"function","function":{...}}` 展平为
   `{"type":"function","name":...,"parameters":...}`，但请求仍然发往 `/chat/completions`。
   本次将展平逻辑整合进 Responses 分支，并同时完成请求地址、消息、响应、工具结果的转换。
   Chat Completions 分支使用它对应的嵌套工具定义。

   你原有的 `flagscale_agent/react/providers/openai_provider.py.bak` 还在，也包含在迁移包中。
   已通过逐字节比较确认：这个 `.bak` 是当前基准提交的上游原版，不是旧展平补丁的副本。
   新机器只需使用迁移包中的完整修复，不要再叠加旧工具展平补丁。

   协议配置有三个值：

   | `openai_api` | 行为 |
   | --- | --- |
   | `responses` | 直接调用 `/v1/responses`；这是当前模型和中转的推荐配置。 |
   | `chat_completions` | 固定调用 `/v1/chat/completions`。 |
   | `auto` | 默认先尝试 Chat Completions；收到明确的模型/接口协议不支持的 HTTP 400 时切换 Responses，并在本次运行后续请求中继续使用。其他错误仍然报出。 |

   `provider: openai` 表示使用 OpenAI SDK 适配器；实际请求发送到 `base_url` 指定的中转。
   `base_url` 写到 `/v1` 即可，SDK 会追加 `/responses`，不要在配置中重复追加这个路径。
   `gpt-6.1-sol` 是当前配置中的模型名；在其他服务商上使用时，需要该服务商确实提供这个名字。

   本机生成的归档为 `/workspace/flagscale-agent-migration.tar.gz`。
   将它下载或复制到新机器的主目录 `~`。包内有：

   - `FlagScale-Agent/`：修复后的完整项目源码，包含测试和原 `.bak`，不含 `.git`。
   - `flagscale-agent-responses.patch`：相对基准提交的完整修复，包含新增测试文件。
   - `BASE_COMMIT.txt`：基准提交 `4dff90ce84a7e8cfaac1af9a83f558baacc28d51`。
   - `agent.yaml.example`：配置模板，密钥是占位符。
   - `SOURCE_MANIFEST.json`：源码文件 SHA-256，用于核对副本。
   - `VALIDATION.txt`：补丁重放与验证结果。
   - `迁移与配置说明.md`：本说明。

   当前修复尚未提交或推送到官方 GitHub。单独重新克隆官方仓库不会自动包含这些改动。
   迁移包不包含你的真实 API 密钥、`~/.flagscale` 会话、历史记录或自定义技能。
   如需旧会话或自定义技能，请另行复制；启动一个全新实例不需要这些历史数据。

3. **在新机器解压并安装修复后的源码**

   ```bash
   cd ~
   tar -xzf flagscale-agent-migration.tar.gz
   cd ~/flagscale-agent-migration/FlagScale-Agent
   pip install -e .
   ```

   `-e .` 是可编辑安装，程序直接使用这个目录中的源码。因此安装后不要删除或搬动这个源码目录。
   如需搬动，进入新位置重新执行安装命令。
   安装会按照项目的依赖声明安装所需 SDK，OpenAI SDK 最低版本为 `1.66.0`。

4. **确认新参数已经可用**

   ```bash
   flagscale-agent --help
   ```

   帮助中应当出现 `--openai-api`，其可选值是 `auto`、`chat_completions`、`responses`。
   如果没有这个参数，说明当前启动命令还没有加载到此次修复的版本，先确认安装的是迁移包内的源码。

5. **创建配置并填入你自己的密钥**

   以下命令使用默认目录 `~/.flagscale`。先清除当前 Shell 中可能指向旧配置的变量：

   ```bash
   unset FLAGSCALE_AGENT_CONFIG
   unset FLAGSCALE_HOME
   mkdir -p ~/.flagscale
   ```

   如果新机器的 `~/.flagscale/agent.yaml` 已经存在，先备份：

   ```bash
   if [ -f ~/.flagscale/agent.yaml ]; then
       cp -p ~/.flagscale/agent.yaml ~/.flagscale/agent.yaml.before-responses
   fi
   cp ~/flagscale-agent-migration/agent.yaml.example ~/.flagscale/agent.yaml
   chmod 600 ~/.flagscale/agent.yaml
   nano ~/.flagscale/agent.yaml
   ```

   将 `REPLACE_WITH_YOUR_API_KEY` 换成你的真实密钥。配置应类似：

   ```yaml
   provider: openai
   model: gpt-6.1-sol
   api_key: "替换为你的真实密钥"
   base_url: https://api.codexzh.com/v1
   openai_api: responses

   max_iterations: 200
   max_continuations: 200
   max_context_tokens: 0
   max_output_tokens: 8192
   thinking_budget: 0
   ```

   nano 保存为 `Ctrl+O`、回车，退出为 `Ctrl+X`。没有 nano 时可以使用你习惯的文本编辑器。
   如果从旧机器复制已可用的配置，保留原有密钥、模型和地址，只需添加或更新唯一的
   `openai_api: responses` 行，不要重复写同名配置项。

   也可以不在 YAML 中填写 `api_key`，改为在当前 Shell 中设置 `OPENAI_API_KEY`。
   此时要删除 YAML 中的 `api_key` 行；保留占位符会优先使用占位符。

   配置优先级是显式命令行参数 → YAML → 未配置字段的环境变量 → 程序默认值。
   默认自动查找 `~/.flagscale/agent.yaml`；`FLAGSCALE_HOME` 会改变默认状态目录，
   `FLAGSCALE_AGENT_CONFIG` 可以指定自动加载的配置文件，`--config` 可以显式指定文件。

6. **先测试文本，再测试工具调用**

   ```bash
   flagscale-agent --config ~/.flagscale/agent.yaml "只回复 OK"
   ```

   看到正常回答后，再执行：

   ```bash
   flagscale-agent --config ~/.flagscale/agent.yaml "使用 shell 工具运行 uname -s，并告诉我输出"
   ```

   第二条用于确认工具执行后的结果能够再发送给模型。原项目的 Guard 仍会参与检查；
   本次没有移除或放宽 Guard。没有 GPU 的机器也可以用 `uname -s` 测试。

   本机自动测试使用模拟 HTTP 和真实 OpenAI SDK，覆盖协议与多轮交互；真实中转已由你反馈可用。
   新机器仍需有有效密钥、可用模型和到中转地址的网络连接。

7. **日常启动**

   完成安装和 YAML 配置后，直接启动：

   ```bash
   flagscale-agent --config ~/.flagscale/agent.yaml
   ```

   YAML 已经写了 `provider: openai` 和 `openai_api: responses`，因此不必反复输入长参数。
   如果需要显式指定协议，等价命令为：

   ```bash
   flagscale-agent --config ~/.flagscale/agent.yaml --provider openai --openai-api=responses
   ```

   命令行参数使用连字符 `--openai-api`，YAML 键使用下划线 `openai_api`。
   `--openai-api` 需要值，不能单独输入。

10. **出现错误时按以下对应关系检查**

    | 现象 | 检查方式 |
    | --- | --- |
    | `No such option: --openai-api` | 确认安装的是迁移包内的源码，并用 `--help` 检查修复版本的新参数是否存在。 |
    | `--openai-api requires an argument` | 使用 `--openai-api=responses`，或把协议写进 YAML 后只运行简短启动命令。 |
    | 模型不支持 Chat Completions | 确认当前配置里是 `openai_api: responses`，且实际加载了该文件。 |
    | 找不到 API key | 确认 YAML 中填入真实密钥，或删除该行并正确设置 `OPENAI_API_KEY`。 |
    | HTTP 401 / 403 | 核对服务商地址、密钥和模型权限。 |
    | DNS、超时、连接失败 | 在新机器检查中转网络连通性和代理配置。 |
    | 工具被 Guard 拦截 | 查看 Guard 的具体理由；此次协议修复没有取消 Guard。 |

    当前旧机器的真实配置未被本次迁移打包操作修改，它尚未持久化 `openai_api` 字段；
    当前通过显式参数或自动协议切换运行。新机器按模板设置为 `responses` 后，可以直接使用简短启动命令。
